# JW-CAD/JWWへの取り込み方法

導入手順そのものは `windows_setup.md` にまとめてあります。ここでは
仕組みと、書式が合わなかったときの調整方法を説明します。

## 方法1: DXF読み込み（確実・推奨）

`jwcad-volume` はDXFファイルを出力します（`output.dxf_path`）。JWWの
DXF読込機能でこのDXFを読み込めば、敷地境界線・各段のボリューム輪郭
（平面）・断面・サマリーテキストが図面に取り込まれます。

| レイヤー | 内容 |
|---|---|
| `SITE` | 敷地境界線 |
| `ENVELOPE-PLAN` | 各高さ段の平面輪郭（段ごとに色分け） |
| `ENVELOPE-PLAN-TEXT` | 各段の高さ範囲ラベル |
| `SECTION-GL` | 断面図のグランドライン |
| `ENVELOPE-SECTION` | 断面図（切断位置は `output.section_axis` / `section_position` で指定） |
| `SUMMARY` | 敷地面積・延床面積・天空率適合状況・日影規制適合状況などのテキスト |

JWWの標準機能のみに依存するため、外部変形として登録しなくても
「コマンドで実行 → DXFをJWWで開く」だけで使えます。

## 方法2: 外部変形として登録

### 仕組み

1. JWWの [その他]-[外部変形] でバッチを選ぶ
2. JWWが選択図形を `JWC_TEMP.TXT` というテキストに書き出す
3. バッチが `jwcad_volume_gaihen.exe` を起動する
4. exeが `JWC_TEMP.TXT` を読み、敷地形状を組み立て、計算し、
   結果を同じファイルに上書きする
5. JWWが `JWC_TEMP.TXT` を読み戻して図面に反映する

### 敷地条件の渡し方

図面から読み取れるのは**敷地の形と線色**だけなので、役割分担しています。

| 情報 | どこで指定するか |
|---|---|
| 敷地の形（頂点座標） | JWWの図面（外形線を選択） |
| 各辺の境界種別（道路/隣地/北側） | JWWの**線色**（既定: 1/2/3） |
| 道路幅員 | `gaihen_params.yaml` の `road_width_m` |
| 用途地域・容積率・建蔽率 | `gaihen_params.yaml` の `zoning` |
| 日影規制の時間数・測定線 | `gaihen_params.yaml` の `shadow` |

線色で境界種別を指定するのは、CADで自然に描き分けられるためです。
`boundary_colors` で対応を変更できます。

### 本パッケージが想定しているJWC書式

`jwcad_volume/jwc.py` は次の理解で実装しています。

- 文字コードは Shift-JIS、改行は CRLF
- 座標は実寸の **mm**（`units_per_meter` で換算。m単位作図なら1を指定）
- `#` で始まる行はコメント/ヘッダ
- 属性は状態行で指定し、以降の図形に適用:
  `lg<n>`=レイヤグループ / `ly<n>`=レイヤ / `lc<n>`=線色 / `lt<n>`=線種
- 図形行:
  - 線: 数値4個 `x1 y1 x2 y2`
  - 円/円弧: `ci cx cy r ...`
  - 文字: `ch x1 y1 x2 y2 文字列`
  - 点: `pt x y`

> **この書式は実機のJWWで検証できていません。** 開発はLinux
> サンドボックス上で行っており、JWW本体を実行する手段がないためです。
> 読み取り側は「解釈できない行は捨てずに退避する」寛容な作りにしてある
> ので、実際の書式が違っていても、まず何が来ているかを確認できます。

### 書式が合わないときの調整

`診断_データ確認.bat` を実行すると、JWWが渡してきた生データ
（`JWC_SAMPLE.TXT`）と、本ツールの読み取り結果（`診断結果.txt`）が
得られます。判断のしかたは `windows_setup.md` の「B-5」を参照してください。

書式の食い違いが分かった場合、直す場所は次の3か所だけです。

| 症状 | 直す場所 |
|---|---|
| 線分が読めない（`unknown` に入る） | `jwc.py` の `parse_jwc`（図形行の判定） |
| 書き戻しをJWWが受け付けない | `jwc.py` の `JwcWriter`（出力の組み立て） |
| そもそもバッチが起動しない/データが来ない | `.bat` 冒頭の `REM #...` 制御行 |

計算エンジン側（斜線制限・天空率・日影規制）はこの書式に一切依存しない
ので、書式の調整が計算結果に影響することはありません。

### エラー時のふるまい

敷地形状が閉じていない、設定ファイルが無い、といった場合、exeは
**図面に何も作図しないデータを返します**（壊れた図形を描き込まない
ため）。原因はコンソールと、返却ファイルのコメント行に残ります。
