## 0. この文書について

MVCE2（`mvce/` パッケージ、`docs/mvce/mvce2_log.md` に実装記録があります）は
「日影規制・斜線制限・容積率をふまえて、敷地に建てられる最大容積を求める」
という一点に絞ったエンジンでした。3D出力は単一HTMLのCanvas 2D簡易ビューア
のみ、床面積は「体積 ÷ 階高」の1つの数字だけで、階ごとの内訳や、外部の
BIM/3D CADツールへ渡せる形式は持っていません。

**MVCE3はMVCE2の全体を再検討したうえでの追加機能です。** 法規カーネル
（斜線制限・日影規制・容積率・天空率の判定ロジック）はMVCE2のものを
そのまま使い、変更しません。追加するのは次の2点だけです。

1. **3Dモデリングの強化** — FreeCADまたはBlenderのPython APIを使い、
   MVCE2の計算結果（階ごとのボリューム）から実際のCAD/3Dモデルを組み立てる
2. **各階床面積表のExcel出力** — 階ごとの床面積を表にまとめ、`.xlsx` で
   出力する

再検討の結論は「**法規カーネルを壊さず、外側に機能を足す**」です（1章参照）。
`mvce/` パッケージのリネーム・再構成は伴いません。

---

## 1. MVCE2の再検討 — 何を変え、何を変えないか

### 1.1 変えないもの

MVCE2の法規カーネルは、条文照合台帳（`mvce2_log.md` の「照合で見つかった
もの」表・累計30件超）に支えられた、この計算エンジンの本体です。ここに
手を入れる理由がMVCE3にはありません。**MVCE3はMVCE2の計算結果を消費する
だけで、計算方法そのものには一切関与しません。**

具体的には、次のものは無傷で残ります。

- `mvce/regulations/` 以下すべて（斜線制限・日影・天空率・高度地区）
- `mvce/solvers/optimizer.py`（ボクセル最適化）・`mvce/inverse/`（逆日影）
- `mvce/verdict.py`（`Verdict` / `UNDETERMINED` の型と不変条件）
- `mvce/profiles/`（プロファイル機構）
- 既存の出力（DXF図面・簡易3Dビューア・サマリー文字列）

### 1.2 変える／足すもの

| 課題 | MVCE2の状態 | MVCE3での対応 |
|---|---|---|
| 3Dモデルが検討用の簡易表示だけ | `viewer3d.py` の単一HTML（Canvas 2D、外部ツールへ渡せない） | FreeCAD/Blenderで実際のソリッド/メッシュを組み立て、`.FCStd`/`.step`/`.ifc`/`.blend`/`.glb`/`.obj` で書き出す（4章） |
| 床面積が1つの数字だけ | `OptimizeResult.total_floor_area_m2`（体積÷階高） | 階ごとの内訳を表にし、Excel（`.xlsx`）で出力する（3章） |

### 1.3 「MVCE3」という名前について

MVE→MVCEのリネーム（`mvce2_log.md` Phase 0）は、パッケージ名・DXFレイヤ名・
CLIコマンド名すべてを実際に付け替えるリネームでした。**MVCE3はそれとは
性格が違います。** パッケージは引き続き `mvce/` のままで、`mvce3` という
名前のパッケージやコマンドは作りません。「MVCE3」は**MVCE2に3D強化と
床面積表を足した版**を指す呼び名であり、`pyproject.toml` の
バージョン番号やドキュメントの版数で管理します（パッケージの再配置は
行いません）。理由は1.1節のとおり、法規カーネルには触れておらず、
リネームに見合うだけの構造変更が無いためです。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 階（フロア） | `floor_height_m` ごとに区切った1層。`mvce/floors.py` の `FloorSlab` |
| 床面積（MVCE3の意味） | その階に属する `Block`（`mvce/massing.py`）の水平投影面積の合計。**法令上の「床面積」（令2条1項3号）と同じではありません**（3.3節） |
| 3Dモデル化バックエンド | 階のリストから実際の3D形状を組み立てる実装。`mesh`（既定・自前実装）／`freecad`／`blender`（4.2節） |
| 既定バックエンド | 追加インストールなしで動くバックエンド。MVCE3では `mesh` |

## 3. 各階床面積表（Excel出力）

### 3.1 目的

MVCE2の最大ボリューム計算は、階ごとにマスを積み上げた結果を持っています
（`solvers/optimizer.py` の `_floors_to_blocks`）。この内訳は今までサマリーの
1行（延床面積の合計）に潰されていました。**階ごとの数字をそのまま表として
取り出せるようにする**のが目的です。

### 3.2 機能要件

| # | 要件 |
|---|---|
| F-1 | `OptimizeResult`（`mvce.solvers.optimizer.optimize()` の戻り値）から、階ごとの床面積・階高・累計延床面積を求められること |
| F-2 | 上記を Microsoft Excel（`.xlsx`）形式のファイルとして書き出せること |
| F-3 | 表には敷地名・敷地面積・建築面積・延床面積・達成容積率／適用容積率も併記すること（既存のサマリーと同じ情報を Excel でも読めるようにする） |
| F-4 | CLI（`mvce`コマンド）から `--floor-area-xlsx ファイル名` で出力できること。設定YAMLの `output.floor_area_xlsx_path` でも指定できること |
| F-5 | 分棟（同じ階に離れた複数の建物部分がある場合）・中抜き（穴のある階）を検出し、表の備考欄に注記すること |

### 3.3 非目標（やらないこと）

法令上の「床面積」（建築基準法施行令2条1項3号）や「容積率算定用床面積」
（同項4号の不算入部分を除いたもの）を正確に算定することは、**MVCE3の
範囲外です**。理由は次のとおりです。

- MVCE2の外郭線は「壁面後退線で囲まれた、建物を置ける範囲」を表す多角形
  であり、壁芯・内法・仕上げ厚のどれとも紐付いていません
- 用途別の内訳（住戸・共用部・駐車場・機械室等）を持つデータモデルが
  そもそも存在しません
- 令2条1項4号（吹抜け・共同住宅の共用廊下等の不算入）・令2条3項
  （自動車車庫等の緩和、床面積の1/5を限度）はいずれも未実装です

これらを実装せずに「床面積表」と呼ぶと、確認申請の書類と誤認されるおそれが
あります。そのため出力する Excel には**必ず注記**（`DISCLAIMER_JA`、
`mvce/reports/floor_area_table.py`）を入れ、READMEにも明記します
（原則F：出典・限界を隠さない）。

### 3.4 データの出どころ

新しい面積計算は一切行いません。`mvce/massing.py` の `Block`
（`footprint: Polygon`、`z_bottom`、`z_top`）を `z_bottom` でグループ化し、
同じ階の `footprint` 面積を合計するだけです（`mvce/floors.py`）。この値は
既存の `OptimizeResult.total_floor_area_m2`（体積÷階高）の内訳そのものと
数学的に一致します（`tests/mvce/test_floors.py`
`test_total_floor_area_matches_optimize_result`）。

## 4. 3Dモデリングの強化

### 4.1 目的と背景

MVCE2の3D出力（`mvce/io/viewer3d.py`）は、外部ライブラリを使わない単一HTMLの
Canvas 2Dペインターズアルゴリズム描画です。検討用の簡易表示としては
機能しますが、次のことができません。

- 他のCAD/BIMソフトへ持ち出す（ファイル形式がHTML専用の内部JSON）
- 正確なソリッド（閉じた立体）としての体積・面積の再計算
- IFC等の標準BIM形式での納品

そこで、**FreeCADまたはBlenderのPython APIを使って実際の3D形状を組み立てる**
機能を追加します。

### 4.2 なぜ2つのツールを選択式にするか

FreeCADとBlenderは性格が異なります。

| | FreeCAD | Blender |
|---|---|---|
| 得意分野 | CAD（B-rep、正確な寸法・面）、建築・BIM向けワークベンチ（Arch/BIM） | 3DCG（メッシュ、レンダリング、アニメーション） |
| 中抜き（穴）の表現 | `Part.Face` が内側ワイヤを直接扱える。**正確** | 面に穴を直接持てず、ブーリアン演算が要る |
| 出力形式 | `.FCStd`・**IFC**・STEP等、BIM/CAD連携に強い | `.blend`・`.glb`・`.obj`等、ビジュアライズ・ゲームエンジン連携に強い |
| 用途に合っているか | 床面積表・IFC納品と相性が良い | パース・アニメーション・他ツールでの表示と相性が良い |

どちらか一方に決め打ちせず、**利用者の用途に応じて選べる**ようにします。
どちらも**アプリケーション本体のインストールが要り、pipだけでは入りません**
（4.4節）。そのため、追加インストールなしで動く3つめの選択肢
（`mesh` バックエンド）を既定にします。

### 4.3 機能要件

| # | 要件 |
|---|---|
| F-6 | `OptimizeResult` の階ごとのボリュームから、3Dの立体モデルを組み立てられること |
| F-7 | バックエンドを `mesh`（既定）／`freecad`／`blender` から選べること |
| F-8 | `mesh` バックエンドは追加インストールなしで動作し、Wavefront OBJ形式で書き出せること |
| F-9 | `freecad` バックエンドはFreeCADの `Part` モジュールで立体を組み立て、`.FCStd`/`.step`/`.ifc` で書き出せること |
| F-10 | `blender` バックエンドはBlenderの `bpy` でメッシュを組み立て、`.blend`/`.glb`/`.gltf`/`.obj` で書き出せること |
| F-11 | 指定したバックエンドが実行環境に無い場合、**黙って他のバックエンドに切り替えず**、原因と対処法を含むエラーで止まること（原則H） |
| F-12 | CLIから `--model3d-out ファイル名 --model3d-backend {mesh,freecad,blender}` で出力できること |

### 4.4 非目標・既知の制約

- **FreeCAD・Blenderはpipパッケージではありません。** どちらもアプリケー
  ション本体のインストールが要り、`pip install` だけでは使えるように
  なりません（利用者側の環境構築が必要。詳細は
  `mvce/model3d/freecad_backend.py`・`blender_backend.py` のdocstring）
- **`freecad`／`blender`バックエンドは、この開発・テスト環境で実行して
  確認できていません。** FreeCAD・Blenderのどちらもこのリポジトリの
  実行環境にインストールされていないためです。公開されているPython API
  の仕様どおりに実装していますが、実機での動作確認は利用者側で行って
  ください（原則F：検証できていないことを検証済みと書かない）
- `mesh` バックエンド（既定）と `blender` バックエンドは、**中抜き（穴の
  ある階）を外周のみで描画**します。正確な穴を再現できるのは `freecad`
  バックエンドだけです（4.2節）
- テクスチャ・マテリアル・建具（窓・ドア）等の意匠情報は持ちません。
  あくまで「階ごとのボリューム」をそのまま立体化したものです

## 5. 非機能要件

| # | 要件 |
|---|---|
| N-1 | MVCE2の既存テスト（`tests/mvce/`）が引き続きすべて緑であること（受入基準は6章） |
| N-2 | 追加機能（床面積表・`mesh`バックエンド）は追加の実行時インストールなしで動作すること（`openpyxl`のみ追加依存。`pip install "jwcad-volume[xlsx]"`） |
| N-3 | `freecad`／`blender`バックエンドを使わない利用者には一切影響が無いこと（import は使うときだけ行う遅延importとする） |

## 6. 受入基準

1. `mvce/reports/floor_area_table.py` から、既存の `OptimizeResult` を
   使って Excel ファイルを生成でき、階数分の行と合計行があること
2. `mvce/model3d/` の `mesh` バックエンドで OBJ ファイルを実際に生成でき、
   頂点数・面数が階数・多角形の頂点数から計算できる値と一致すること
3. `freecad`／`blender` バックエンドは、ツールが無い環境で
   `Model3DBackendUnavailable` を送出し、原因と対処法がメッセージに
   含まれること
4. CLIに `--floor-area-xlsx`・`--model3d-out`・`--model3d-backend` が
   追加され、設定YAMLの `output.*` からも同じ指定ができること
5. 既存の自動テスト（MVCE2分）が1件も壊れないこと
