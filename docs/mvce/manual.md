# MVCE 取扱説明書

**MVCE（Maximum Volume Engine）** — 日影規制・斜線制限（天空率を含む）・
容積率をふまえて、敷地に建てられる**最大容積**を試算するツールです。

この説明書は、実際にMVCEを操作して敷地のボリュームチェックを行う方向けの
手順書です。内部の計算方法やアルゴリズムの詳細は `design_spec.md`
（設計仕様書）を参照してください。

> **設計初期段階の検討用です。確認申請には使えません。**
> 天空率・日影図とも測定点は近似計算で、告示が定める厳密な方法には
> 準拠していません。詳しくは本書「9. 免責事項」および `disclaimer.md` を
> 必ず読んでください。

## 1. MVCEでできること

敷地の形・道路・用途地域・日影規制の条件を入力すると、

- 道路斜線・隣地斜線・北側斜線（法56条）、または天空率（法56条7項）
- 容積率（法52条）・建蔽率
- 日影規制（法56条の2）

を**すべて満たす範囲で、最大の延床面積**を自動で探索します。結果は

- 画面に出る計算結果のサマリー（数値と適合判定）
- JW-CADで開けるDXF図面
- ブラウザで回して見られる3Dビューア（HTML）

として出力されます。日影規制がある敷地では、超過している方角の
マス（コマ）だけを狙って下げるため、**建物全体を一律に低くする
やり方より大きな容積**が出ます。屋根越しパターン・棟状パターンという
「規則正しい1〜2枚の勾配面」で削る逆日影の別解も選べます（4.9節）。

## 2. 使う前に：3つの注意

### ① 確認申請には使えません

天空率の測定点配置・投影方法は内部で一貫した近似を使っており、告示が
定める厳密な方法には準拠していません。日影図（5m/10m測定線・等時間
日影線とも）も等間隔サンプリングの近似です。**「このくらい入りそうだ」
という設計初期段階の目安**として使い、最終的な確認申請図面は資格者が
別途作成してください。

### ② 数値は必ず自分で確認してください

日影規制の**測定面・規制時間**、**容積率・建蔽率**、**絶対高さ制限**の
有無、**緩和対象**（公園・水面・線路敷）になるかどうかは、すべて
都市計画と条例で決まります。MVCEはこれらに既定値を持たず、必ず
入力してもらう作りになっています。役所の都市計画課や自治体のホーム
ページで確認してから入力してください。

### ③ 貪欲法であり、大域最適解ではありません

MVCEの探索は「その時点で一番効率のよい一手」を積み重ねる方式です。
理論上の最大値そのものではなく、**この条件ならこのくらいは入る、という
下限の目安**です。メッシュを細かくする（`--cell 1.0` など）と精度は
上がりますが、計算時間も増えます。

## 3. 始め方（3つの方法）

どれも同じ計算エンジンを使っています。用途に応じて選んでください。

| 方法 | こんなときに | インストール | DXF出力 |
|---|---|---|---|
| A. ブラウザ版 | とりあえず条件をふって感触をつかみたい、DXF図面も要る | 不要 | できる |
| B. Windows版（バッチファイル） | 実際の敷地の図面（DXF）から読み込みたい | Python（初回のみ） | できる |
| C. コマンド版 | 複数敷地をまとめて処理する、細かく制御したい | Python | できる |

### A. ブラウザ版（一番簡単・インストール不要）

1. `web/mvce/index.html` をダブルクリックして開く
   （配布用の単一HTMLが欲しい場合は `python3 tools/build_mvce_web.py` を
   実行すると `dist/MVCE.html` が1つ作れます。USBメモリや
   メールでそのまま渡せます）
2. 左側のフォームに敷地条件を入力する（6つのセクション。4章で詳しく
   説明します）
3. 右側に平面図がその場で更新されます。「3D」タブに切り替えると
   マウスで回せる3D表示になります
4. 通信は一切行いません。オフラインで動きます

条件を詰めたら「設定YAMLを保存」でファイルに書き出せます。これを
そのままB・Cの入力（`自分の敷地.yaml` 相当）として使えます。「敷地を
読み込み」ではYAMLに加えてJSON/CSV形式の敷地データも取り込めます。
「DXF図面を保存」でJW-CADが読める形式のDXFをブラウザから直接
保存できます。ただし**DXF図面（線分）から敷地の形を読み込む機能は
Windows版・コマンド版のみ**です。詳しくは `web_ui.md` を参照してください。

### B. Windows版：ダブルクリックで実行（DXF図面が必要な場合）

もっとも手軽にDXF図面まで作る方法です。

1. リポジトリのフォルダを開く（`結果.dxf` の隣に `MVCE実行.bat` がある
   フォルダです）
2. `MVCE実行.bat` をダブルクリックする
   - 初回はPythonの有無を確認し、無ければ案内が出ます（[3-1](#3-1-初回だけpythonの準備) 参照）
   - 必要なパッケージも自動でセットアップされます（数分かかることがあります）
   - `自分の敷地.yaml` が無い場合は、テンプレート
     （`examples\敷地入力テンプレート.yaml`）からその場で作られます
3. 一度実行が終わったら、`自分の敷地.yaml` をメモ帳などで開き、
   **★の付いた行**を実際の敷地の値に書き換えます（4章参照）
4. もう一度 `MVCE実行.bat` をダブルクリックすると、書き換えた内容で
   計算されます
5. できあがった `結果.dxf` と `結果_3d.html` が同じフォルダに出ます

特定のYAMLファイルを使いたい場合は、そのファイルを `MVCE実行.bat` の
上に**ドラッグ＆ドロップ**すると、そのファイルを設定として実行します。

#### 3-1. 初回だけ：Pythonの準備

`MVCE実行.bat` はPythonが入っていない場合、エラーメッセージでその場で
案内します。

1. https://www.python.org/downloads/ からダウンロード
2. インストーラの最初の画面で **「Add python.exe to PATH」に必ずチェック**
   を入れる（これを忘れるとPythonが見つからないままになります）
3. インストール後、`MVCE実行.bat` をもう一度ダブルクリックする

### C. コマンド版（コマンドプロンプト・複数敷地の一括処理など）

```bash
mvce 自分の敷地.yaml --dxf-out 結果.dxf --html-out 結果_3d.html --cell 2.0
```

| オプション | 意味 |
|---|---|
| `--dxf-out ファイル名` | DXF図面の出力先（設定ファイルの `output.dxf_path` を上書き） |
| `--html-out ファイル名` | 3Dビューアの出力先 |
| `--cell 数値` | メッシュの幅(m)をまとめて指定。細かくすると精度は上がるが計算は遅くなる |
| `--no-shadow` | 日影規制のチェックを省略する |
| `--envelope voxel\|lean_to\|ridge` | 日影規制への対応方法（4.9節） |
| `--dxf-units 数値` | DXFで1mを何単位として書くか（既定1000=mm） |
| `--dxf-backend r12\|ezdxf` | DXFの書き出し方式（既定 `r12` がJW-CAD向け） |

Python環境がすでにあり、コマンドラインに慣れている場合はこちらが
最速です。Windows版（B）は内部でこれと同じ `python -m mvce.cli` を
呼んでいるだけです。

## 4. 敷地データの作り方

`自分の敷地.yaml`（またはお好きな名前のYAMLファイル）に、敷地の条件を
書きます。全項目のコメント付きサンプルは
`examples/mvce_sample.yaml`（詳しい説明版）と
`examples/敷地入力テンプレート.yaml`（★の行だけ埋める簡易版）に
あります。以下は各項目の考え方です。

### 4.1 敷地の形

3通りの書き方があり、どれか1つを選びます。

```yaml
site:
  # 長方形が一番かんたん
  rectangle:
    width_m: 30    # 間口（X方向）
    depth_m: 20    # 奥行（Y方向）

  # 変形地は頂点を反時計回りに書く（単位はm）
  # points:
  #   - [0, 0]
  #   - [25, 0]
  #   - [30, 18]
  #   - [0, 20]

  # 手元にCADの敷地図があるならDXFから読み込める
  # dxf:
  #   path: 敷地図.dxf
  #   units_per_meter: 1000   # mmで作図しているなら1000、mなら1
```

DXFから読み込む場合、閉じたポリラインか、つながった線分から敷地の
輪郭を読み取ります。線分で描いた図面は**レイヤ名**から辺の種別
（道路・隣地）を推測します。

### 4.2 真北

```yaml
  north_angle_deg: 0   # 図面の上(+Y)が真北なら0
```

図面の上から**反時計回り**に何度ずれているかを指定します。北側斜線と
日影計算はこの向きを基準に行われ、出力するDXF・3D表示にも真北記号が
出ます。図面上の向きと実際の方角がずれていると、北側斜線や日影の
判定そのものが誤った方角で行われるので、最初に確認してください。

### 4.3 各辺の種別（前面道路・隣地）

頂点の並び順に対応します。長方形なら「下→右→上→左」の順です。

```yaml
  edges:
    - kind: road            # 前面道路
      road_width_m: 6.0
    - kind: adjacent        # 隣地
    - kind: adjacent
    - kind: adjacent
```

道路が2本以上ある場合は、該当する辺をすべて `kind: road` にすれば
**令132条（2以上の前面道路）の読み替え**が自動で適用されます。容積率も
**法52条2項**（前面道路が12m未満なら幅員×係数で頭打ち）が自動で
反映されます。

### 4.4 緩和対象（公園・水面・線路敷）

```yaml
    - kind: adjacent
      relaxation: {kind: water, width_m: 4.0}   # park（公園）/ water（水面）/ railway（線路敷）
```

隣地の外側が公園・水面・線路敷に接する場合、辺ごとに追記すると斜線
制限の緩和が効きます。**斜線の種類ごとに対象が違う点に注意してください**
（例：北側斜線は公園・広場が対象外）。詳細は `legal_basis.md`。

高低差がある場合は `ground_level_diff_m` を追加します（1m以上で
緩和が効きます）。

### 4.5 壁面後退距離

```yaml
  wall_setback_m: 1.0   # 全辺共通の既定値
  edges:
    - kind: road
      wall_setback_m: 1.5   # 辺ごとに変える例
```

建物を境界線から下げる距離です。**斜線制限の後退緩和・天空率・
建物を置ける範囲の3つ**に同時に効きます。

### 4.6 用途地域・容積率・建蔽率

```yaml
  zoning:
    zone_type: 1res     # 下表から選ぶ
    far_ratio: 200       # 容積率(%)。都市計画で定められた値
    coverage_ratio: 60   # 建蔽率(%)
    # absolute_height_limit_m: 10   # 低層住居専用等で絶対高さ制限がある場合
  floor_height_m: 3.2    # 階高(m)
```

| `zone_type` | 用途地域 | `zone_type` | 用途地域 |
|---|---|---|---|
| `1low` | 第一種低層住居専用 | `2mid` | 第二種中高層住居専用 |
| `2low` | 第二種低層住居専用 | `1res` | 第一種住居 |
| `denen` | 田園住居 | `2res` | 第二種住居 |
| `quasi_res` | 準住居 | `neighbor_commercial` | 近隣商業 |
| `commercial` | 商業 | `quasi_industrial` | 準工業 |
| `industrial` | 工業 | `industrial_exclusive` | 工業専用 |
| `1mid` | 第一種中高層住居専用 | `unspecified` | 用途地域の指定なし |

### 4.7 日影規制

対象区域でなければ `shadow:` のセクションごと削除してください。
対象区域の場合は、**測定面と規制時間を条例で確認して**入力します
（既定値は用意していません＝黙って計算が進まないようにしています）。

```yaml
shadow:
  measurement_height_m: 4.0   # 1.5 / 4.0 / 6.5 のいずれか
  line_5m_max_hours: 5.0      # 敷地境界から5m超10m以内の規制時間
  line_10m_max_hours: 3.0     # 10m超の規制時間
  latitude_deg: 35.7          # 敷地の緯度（東京35.7 / 大阪34.7 / 札幌43.1 など）
  hokkaido: false             # 北海道なら true（測定時間が真太陽時9〜15時になる）
```

既定では、超過している測定点について**そこを実際に日影にしている
マスだけ**を下げます（自由形）。建物全体を一律に低くする方式より
容積を大きく取れますが、結果はマスごとにばらばらな階段状になります。

等時間日影線（2時間線・3時間線など）も欲しい場合は `isochrone_hours` に
時間のリストを指定します（既定は空＝作図しない）。建物が高いほど計算に
時間がかかることがあります。

```yaml
shadow:
  ...
  isochrone_hours: [2.0, 3.0, 4.0, 5.0]   # 空なら作図しない（既定）
  isochrone_grid_interval_m: 2.0          # 等時間日影線を求めるグリッドの間隔
  # isochrone_margin_m を省略すると建物高さから自動計算
```

### 4.8 メッシュの粗さ

```yaml
mesh:
  cell_size_x_m: 3.0
  cell_size_y_m: 3.0
  mesh_angle_deg: 0     # 道路に平行に割り付けたい場合など
```

敷地を刻む格子の幅です。**細かくするほど精度（容積）は上がりますが
計算時間も増えます**。最初は3.0m程度で様子を見て、案がまとまってきたら
1.0〜2.0mに細かくして詰める、という使い方をおすすめします。

### 4.9 逆日影：屋根越しパターン・棟状パターン

日影規制の解消方法を選べます。

```yaml
mesh:
  envelope_family: voxel   # voxel（既定）/ lean_to（屋根越し）/ ridge（棟状）
```

| 値 | 内容 | 容積 |
|---|---|---|
| `voxel`（既定） | マスごとに独立に下げる自由形。最も容積を稼げるが、結果はマスごとの階段状 | 最大 |
| `lean_to` | 逆日影・屋根越しパターン（片流れ屋根に相当）。1枚の勾配面で規則正しく後退 | やや少ない |
| `ridge` | 逆日影・棟状パターン（切妻屋根に相当）。`lean_to` を含む一般形 | `lean_to` 以上・`voxel` 以下 |

棟（稜線）の向きは、**日影規制を最も厳しくしている太陽方位**に自動で
アンカーして探索します（固定ではなく、その方位を中心にした狭い範囲の
探索）。棟の向きを自分で固定したい場合は `roof_fixed_low_azimuth_deg`
を指定してください。結果はサマリーに次のように出ます。

```
　逆日影: 棟状パターン（切妻）/ 棟高8.11m / 低勾配側 方位22° 勾配20度 / 反対側は元の高さ制限のまま
```

DXFには棟の位置が `MVCE-RIDGE` レイヤに描かれます。

### 4.10 天空率（法56条7項）

```yaml
mesh:
  use_sky_ratio: true
  sky_ratio_interval_m: 4.0   # 測定点の間隔(m)
  sky_ratio_n_azimuth: 72     # 天空を何方位で刻むか
```

`true` にすると**斜線制限（道路・隣地・北側斜線）の代わりに天空率で
判定**します。すべての測定点で Ps（計画建築物の天空率）が
Pr（適合建築物の天空率）以上になるまで、足りない点の稜線を作っている
マスだけを下げます。結果はサマリーに次のように出ます。

```
　天空率（法56条7項・30点で判定）: 適合 / 最小余裕 +5.27%（Ps 62.24% ≧ Pr 56.97%）
```

**壁面後退距離を取った敷地ほど有利**です（適合建築物側が後退緩和で
高くなり、かつ計画建築物が測定点から遠ざかるため）。日影規制も
同時に指定した場合は、日影と天空率の**両方を同時に満たす**よう
探索します（片方を解消してから他方に移ると、削り込みが重複することが
あるためです）。

> 天空図の投影方法と測定点配置は内部の近似です。**確認申請の天空率
> 算定には使えません**（2章①参照）。ブラウザ版（3-A）でも「6. 天空率」の
> チェックボックスから同じロジックで検討でき、DXF図面もブラウザから
> 直接保存できます。

## 5. 計算結果の読み方

### 5.1 画面に出るサマリー

実行すると、次のような内容がコンソール（またはバッチファイルの黒い
画面）に表示されます。

```
敷地面積: 600.0 m2
建築面積: 340.0 m2（建蔽率の上限 360.0 m2）
延床面積(概算): 1144.0 m2（容積率の上限 1200.0 m2）
達成容積率: 191%（上限 200% に対して 95%）
最高高さ: 12.80 m
体積: 3660.8 m3
メッシュ: 3.0m × 3.0m / 使用34マス（全40マス）/ 最高4階
上限に達した規制: 日影規制
　日影規制で削った体積: 412.0 m3
　5m〜10mの測定線（5.0時間以内）: 適合 / 最大 5.00時間
　10m超の測定線（3.0時間以内）: 適合 / 最大 2.85時間
```

| 行 | 意味 |
|---|---|
| 建築面積・延床面積 | 実際に計算された値と、条例上の上限の両方を併記 |
| 達成容積率 | 上限に対して何%まで使えたか（100%に近いほど容積率を使い切っている） |
| 上限に達した規制 | 建蔽率・容積率・日影規制・天空率のうち、実際に効いた（頭打ちになった）もの |
| 各測定線の行 | 日影規制・天空率の適合判定と、最も厳しい実測値 |

「上限に達した規制」に**日影規制**とだけ出ている場合、容積率にはまだ
余地があるのに日影規制で頭打ちになっている、ということです。逆に
**容積率**が出ている場合は、日影規制よりも容積率の方が厳しい敷地です。

### 5.2 DXF図面

| レイヤ | 内容 |
|---|---|
| `MVCE-SITE` | 敷地境界線 |
| `MVCE-ROAD` | 前面道路（幅員ぶんの帯・幅員の文字） |
| `MVCE-SETBACK` | 壁面後退線 |
| `MVCE-OUTLINE` | 建物外郭線 |
| `MVCE-MESH` | メッシュの割り付け |
| `MVCE-FLOORS` | 各マスの階数 |
| `MVCE-PLAN-n` | n階の平面輪郭 |
| `MVCE-SHADOW-5M` / `-10M` | 日影の測定線 |
| `MVCE-ISOCHRONE-{時間}H` | 等時間日影線（`isochrone_hours` を指定したときのみ） |
| `MVCE-NORTH` | 真北記号 |
| `MVCE-RIDGE` | 逆日影（屋根越し・棟状パターン）の棟の位置 |
| `MVCE-SUMMARY` | 計算結果の要約 |

JW-CADが読める形式（DXF R12・LINEとTEXTのみ・mm）で書き出します。
開き方は6章を参照してください。

### 5.3 3Dビューア（HTML）

`結果_3d.html` をダブルクリックすると開きます。マウスのドラッグで
回せます。最大ボリューム（オレンジ）と斜線制限のエンベロープ
（青の半透明）を重ねて表示するので、どこが斜線制限で削られているかが
一目で分かります。外部ライブラリもインターネット接続も使わないので、
オフラインのままメールで送ったり別のPCで開いたりできます。

## 6. JW-CADで開く

### 6.1 手順

1. JW-CADで「ファイル」→「開く」
2. ファイルの種類を「DXF」にして `結果.dxf` を選ぶ
3. 読み込みダイアログが出たら既定のままでOK

### 6.2 表示されないとき

読み込みが成功したように見えても図面に何も表示されないことが
あります。まず**「全体表示」**を試してください（縮尺が大きく違う
ためだけ、ということがよくあります）。

それでも見えない場合は、`結果.dxf` を `DXF確認.bat` の上に
**ドラッグ＆ドロップ**してください。JW-CADが読める形式かどうかを
その場で判定します。

```
OK  バージョン: R12 (AC1009)
    要素: {'LINE': 1025, 'TEXT': 105}
OK  要素の種類はJWWが読めるものだけです。
OK  mmで書かれているとみて問題ない大きさです（実寸 約50m）。
OK  文字コード: Shift-JIS (ANSI_932)

判定: JWWで読めるはずです。
```

`判定: JWWで読めるはずです。` と出るのに実際は見えない場合は、
次の切り分け用テストDXFを作って原因を絞り込めます。

```bash
python3 tools/make_jww_test_dxf.py
```

単純なものから順に5つのDXFができます。番号順にJW-CADで開いていき、
どこから表示されなくなるかを見ると原因が1つに絞れます（すべて
10m四方の正方形＋対角線という単純な図形です）。

| ファイル | 足したもの | 表示されなければ疑うもの |
|---|---|---|
| `01_線だけ.dxf` | 線4本のみ | 読込操作そのものを見直す |
| `02_文字あり.dxf` | 半角と日本語の文字 | 文字が原因 |
| `03_レイヤ4枚.dxf` | 名前付きレイヤ4枚 | レイヤ名が原因 |
| `04_レイヤ19枚.dxf` | レイヤ19枚（本番と同じ数） | JW-CADのレイヤ上限(16枚)が原因 |
| `05_ezdxf版.dxf` | 01と同じ図形をezdxfで出力 | ezdxfが付ける要素（ハンドル等）が原因 |

MVCEの既定の書き出し方式（`r12`）は、実機のJW-CADで表示されることを
確認済みです（2026-08）。他のCAD向けに `ezdxf` 方式を使うことも
できますが、その場合はJW-CADでは表示されないことがあります。

## 7. よくあるトラブルと対処

| 症状 | 原因・対処 |
|---|---|
| `MVCE実行.bat` で「Pythonが見つかりませんでした」 | 3-1節の手順でPythonをインストールし、「Add python.exe to PATH」に必ずチェックを入れる |
| 初回実行が数分かかる | 依存パッケージ（numpy・shapely等）の自動セットアップです。2回目以降は数秒で終わります |
| YAML読み込みでエラーになる | 出力先などのパスを `" "`（二重引用符）で囲んでいないか確認してください。`\U` などがUnicodeエスケープと解釈され失敗します。囲む場合は `' '`（一重引用符）を使ってください |
| `edges の数が頂点の数と一致しません` | `points` の頂点数と `edges` の行数が合っていません。長方形なら4本、変形地なら頂点と同じ本数の `edges` が必要です |
| 敷地は入力通りなのに容積が小さい | まず「上限に達した規制」（5.1節）を確認してください。日影規制なら `envelope_family` を変えて比較する、天空率なら壁面後退を増やす、容積率・建蔽率ならメッシュや配置そのものの見直しが必要です |
| 結果がJW-CADで表示されない | 6.2節「表示されないとき」を参照 |
| 図面の縮尺がおかしい（極端に大きい/小さい） | `output.dxf_units_per_meter` を確認。JW-CAD向けの既定は1000（mm）です。mで作図した図面に合わせたい場合は1にしてください |
| Windows exe版 | 現時点では**未検証**です（開発環境がLinuxのため）。当面はPython版（B・C）を使ってください |

## 8. 設定ファイル 全項目リファレンス

```yaml
site:
  name: 敷地名                     # 任意
  points: [[x, y], ...]            # 敷地の形その1：頂点（反時計回り、m）
  rectangle: {width_m, depth_m}    # 敷地の形その2：長方形
  dxf: {path, layer, units_per_meter, default_road_width_m}  # 敷地の形その3：DXF読込
  north_angle_deg: 0               # 真北の角度（図面の上から反時計回り）
  wall_setback_m: 0                # 壁面後退距離の既定値(m)
  edges:                           # 頂点の順に対応する辺の情報
    - kind: road | adjacent        # 前面道路 / 隣地
      road_width_m: 6.0            # kind: road のとき必須
      wall_setback_m: 1.0          # この辺だけ既定値を上書き
      relaxation: {kind: park|water|railway, width_m: 4.0}  # 隣地の緩和
      ground_level_diff_m: 0       # 高低差緩和（1m以上で効く）
  zoning:
    zone_type: 1res                # 4.6節の表から選ぶ
    far_ratio: 200                 # 容積率(%)
    coverage_ratio: 60             # 建蔽率(%)
    absolute_height_limit_m: 10    # 絶対高さ制限（任意）
  floor_height_m: 3.2              # 階高(m)

shadow:                            # 省略すると日影規制のチェックなし
  measurement_height_m: 4.0        # 1.5 / 4.0 / 6.5
  line_5m_max_hours: 5.0
  line_10m_max_hours: 3.0
  latitude_deg: 35.7
  hokkaido: false
  time_step_minutes: 10.0          # 日影の時間刻み
  sample_interval_m: 2.0           # 測定点の間隔
  apply_deemed_boundary: true      # 令135条の12第3項のみなし境界線
  isochrone_hours: []              # 等時間日影線を作図する時間のリスト（空なら作図しない）
  isochrone_grid_interval_m: 2.0   # 等時間日影線のグリッド間隔(m)
  isochrone_margin_m: null         # 省略(null)なら建物高さから自動計算

mesh:
  cell_size_x_m: 3.0
  cell_size_y_m: 3.0
  mesh_angle_deg: 0                # メッシュを回転させたい場合
  coverage_threshold: 0.5          # マスの何割が外郭線に入っていれば採用するか
  use_sky_ratio: false             # true で斜線制限の代わりに天空率判定
  sky_ratio_interval_m: 4.0
  sky_ratio_n_azimuth: 72
  envelope_family: voxel           # voxel / lean_to / ridge（4.9節）
  roof_angle_span_deg: 15.0        # 棟の向きを探索する範囲（±この角度）
  roof_angle_step_deg: 7.5
  roof_offset_steps: 7             # 棟位置の候補数（ridgeのみ）
  roof_pitch_candidates_deg: [20.0, 27.0, 35.0, 45.0]  # 低勾配側の勾配候補
  roof_far_pitch_candidates_deg: [0.0, 20.0, 35.0]     # 反対側（0=制限なし）
  roof_fixed_low_azimuth_deg: null # 棟の向きを固定したい場合

output:
  dxf_path: 結果.dxf
  html_path: 結果_3d.html
  draw_mesh: true
  draw_floor_labels: true
  dxf_units_per_meter: 1000        # JW-CAD向けはmm=1000のまま
  dxf_backend: r12                 # r12（JW-CAD向け）/ ezdxf（他CAD向け）
```

## 9. 免責事項（要約）

- **確認申請には使えません。** 天空率・日影とも内部で一貫した近似を
  使っており、告示が定める厳密な方法には準拠していません
- 日影規制の測定面・規制時間、容積率・建蔽率、絶対高さ制限、緩和対象の
  該非は**すべて自分で条例・都市計画図を確認**してください
- 平均地盤面を算定しておらず、Z=0を地盤面としています（傾斜地では
  実際と乖離します）
- 探索は貪欲法で、**大域最適解ではありません**（下限の目安です）
- 計算結果は**建築士等の専門家による確認・検証を経てから**実務に
  用いてください。重要な案件では特定行政庁への事前相談を行ってください

詳しくは `disclaimer.md` を参照してください。
