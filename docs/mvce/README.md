# MVCE — Maximum Volume Engine

日影規制・斜線制限（天空率を含む）をチェックしながら、敷地に建てられる
**最大容積**を求める計算エンジンです。

> **設計初期段階の検討用です。確認申請には使えません。**
> 必ず `disclaimer.md` を読んでから使ってください。

## 使い方は2通り

### A. ブラウザだけ（インストール不要・おすすめ）

```bash
python3 tools/build_mvce_web.py     # dist/MVCE.html ができます
```

出来たHTMLをダブルクリックすると入力画面が開きます。フォームに敷地条件を
入れて「計算する」を押すだけで、平面図と3Dが出ます。Pythonもコマンド入力も
不要です（詳細は [`web_ui.md`](web_ui.md)）。

計算エンジンはPython版の移植で、**同じ入力なら同じ結果になることを自動
テストで担保**しています（`tests/mvce/test_js_parity.py`）。

### B. コマンド版（DXF図面が必要な場合）

```bash
mvce examples/mvce_sample.yaml
```

設定ファイルを敷地に合わせて書き換えて実行すると、計算結果が表示され、
図面（DXF）と3Dビューア（HTML）が出力されます。

```bash
mvce 敷地.yaml --dxf-out 図面.dxf --html-out 3d.html --cell 2.0
```

`--cell` はメッシュの幅（m）です。細かくすると容積が増えますが計算時間も
増えます。`--no-shadow` で日影のチェックを省略できます。

## できること

### 敷地の入力

5通りの方法があります（`examples/mvce_sample.yaml` 参照）。

| 方法 | 書き方 |
|---|---|
| 座標を直接 | `site.points: [[0,0], [30,0], ...]` |
| 長方形 | `site.rectangle: {width_m: 30, depth_m: 20}` |
| DXFの敷地図 | `site.dxf: {path: 敷地図.dxf}` |
| JSONの敷地図 | `site.json: {path: 敷地図.json}` |
| CSVの敷地図 | `site.csv: {path: 敷地図.csv}` |

DXFは閉じたポリラインか、つながった線分から読み取ります。線分で描いた
場合は**レイヤ名**から境界線の種別を推測します（「道路」「隣地」を含む
レイヤ名）。mmで作図した図面は `units_per_meter: 1000` を指定してください。

JSON・CSVは外部ツール（測量ソフト等）が出力したポリゴンデータをそのまま
取り込むための形式です。

```json
{
  "points": [[0, 0], [30, 0], [30, 20], [0, 20]],
  "edges": [
    {"kind": "road", "road_width_m": 6.0, "wall_setback_m": 1.5},
    {"kind": "adjacent"},
    {"kind": "adjacent", "relaxation": {"kind": "water", "width_m": 4.0}},
    {"kind": "adjacent"}
  ]
}
```

```csv
x,y,kind,road_width_m,wall_setback_m,relaxation_kind,relaxation_width_m,ground_level_diff_m,label
0,0,road,6.0,1.5,,,,南側道路
30,0,adjacent,,,,,,
30,20,adjacent,,,water,4.0,,水路に接する
0,20,adjacent,,,,,,
```

どちらも `edges`（CSVは`kind`列）を省略すると全辺が「対象外」になり、
YAML側の `site.edges` で辺の種別を後から指定できます（DXFのレイヤ名推測が
無い場合と同じ扱い）。CSVはExcelで保存したShift-JISファイルにも対応
（`site.csv: {path: ..., encoding: shift_jis}`）。

### 真北

`site.north_angle_deg` で、真北が図面の上（+Y）からどれだけ反時計回りに
ずれているかを指定します。**北側斜線と日影計算はこの向きを基準に**行われ、
図面にも真北記号が出力されます。

### 前面道路

`kind: road` の辺に `road_width_m` を指定します。複数あってもよく、
**令132条（2以上の前面道路）**の読み替えが自動で適用されます。道路は図面に
幅員ぶんの帯として描かれます。

容積率は**法52条2項**（前面道路12m未満なら 幅員×係数）を自動で反映します。

### 壁面後退距離

`wall_setback_m` を辺ごと（または全体の既定値として）指定します。
斜線制限の後退緩和・天空率・建物を置ける範囲の3つに同時に効きます。

### 公園・水面・線路敷の緩和

```yaml
- kind: adjacent
  relaxation: {kind: water, width_m: 4.0}   # park / water / railway
```

斜線の種類ごとに対象と扱いが違います（詳細は `legal_basis.md`）。
特に**北側斜線は公園・広場が対象外**である点に注意してください。

### 日影規制

```yaml
shadow:
  measurement_height_m: 4.0   # 1.5 / 4.0 / 6.5 から選ぶ
  line_5m_max_hours: 5.0
  line_10m_max_hours: 3.0
```

測定面と規制時間は**条例で決まる**ため、既定値は用意していません。
`apply_deemed_boundary`（令135条の12第3項のみなし境界線）は既定で有効です。

### 逆日影：屋根越しパターン・棟状パターン

既定（`envelope_family: voxel`）は、超過している測定点ごとに**その点を実際に
日影にしているマスだけ**を下げる自由形です。容積は最大化されますが、
結果はマスごとにばらばらな階段状になり、そのままでは建築的な量塊として
使いにくいことがあります。

```yaml
mesh:
  envelope_family: ridge   # voxel（既定） / lean_to（屋根越し） / ridge（棟状）
```

`lean_to`（屋根越しパターン・片流れ）と `ridge`（棟状パターン・切妻。
lean_to を含む一般形）は、代わりに**1〜2枚の勾配面で規則正しく後退**させます。
棟の向きは、**日影規制を最も厳しくしている太陽方位**に自動でアンカーして
探索します（固定ではなく、その方位を中心にした狭い範囲の探索）。

```
　逆日影: 棟状パターン（切妻） / 棟高8.11m / 低勾配側 方位22° 勾配20度 / 反対側は元の高さ制限のまま
```

棟の位置・向き・勾配のどの組み合わせも、`compute_shadow_hours`（shapelyを
使う独立実装）で再検証してから採用します。詳しい仕組みは `mvce/roof_envelope.py`
のdocstring、法令は法56条の2・令135条の12を参照してください。

- 容積は自由形（voxel）以下になります（`ridge` は `lean_to` を含む一般形なので
  `lean_to` 以上、`voxel` 以下）。
- 棟の向きを固定したい場合は `roof_fixed_low_azimuth_deg` を指定します。
- DXFには棟（稜線）の位置が `MVCE-RIDGE` レイヤに描かれます。

### メッシュ

```yaml
mesh:
  cell_size_x_m: 3.0
  cell_size_y_m: 3.0
  mesh_angle_deg: 0     # 道路に平行に割り付けたい場合など
```

メッシュのマスは**建物外郭線で切られます**。マスが敷地や壁面後退線から
はみ出すことはありません。

### 天空率（法56条7項）

```yaml
mesh:
  use_sky_ratio: true
  sky_ratio_interval_m: 4.0   # 測定点の間隔(m)
  sky_ratio_n_azimuth: 72     # 天空を何方位で刻むか
```

`true` にすると斜線制限を外し、代わりに**すべての測定点で Ps ≧ Pr を確認**
します。足りない点があれば、その点の稜線を作っているマスだけを下げて適合
させます。結果はサマリーに出ます。

```
　天空率（法56条7項・30点で判定）: 適合 / 最小余裕 +5.27%（Ps 62.24% ≧ Pr 56.97%）
```

**壁面後退距離を取った敷地ほど有利**です。適合建築物が後退緩和で高くなり、
かつ計画建築物が測定点から遠ざかるので、両側から効きます。

> 天空図の投影方法と測定点の配置は内部で一貫した近似で、告示が定める厳密な
> 測定点設置規則には準拠していません。**確認申請には使えません**
> （`disclaimer.md`）。ブラウザ版でも同じロジックで検討できます。

## 出力

### 図面（DXF）

| レイヤ | 内容 |
|---|---|
| `MVCE-SITE` | 敷地境界線 |
| `MVCE-ROAD` | 前面道路（幅員ぶんの帯・幅員の文字） |
| `MVCE-SETBACK` | 壁面後退線 |
| `MVCE-OUTLINE` | 建物外郭線 |
| `MVCE-MESH` | メッシュの割り付け |
| `MVCE-FLOORS` | 各マスの階数 |
| `MVCE-PLAN-n` | n階の平面輪郭 |
| `MVCE-SHADOW-5M` / `-10M` | 日影の測定線 |
| `MVCE-NORTH` | 真北記号 |
| `MVCE-RIDGE` | 逆日影（屋根越し・棟状パターン）の棟の位置 |
| `MVCE-SUMMARY` | 計算結果の要約 |

JWWが読める形式で書き出します（**DXF R12・LINEとTEXTのみ・mm**）。JWWの
DXF読込は古い仕様しか受け付けず、これを外すと読み込みは成功したように
見えて図面に何も表示されません（`jww_integration.md` に詳細）。

mで作図している図面に合わせたい場合は `--dxf-units 1`、または設定YAMLの
`output.dxf_units_per_meter: 1` を指定してください。

### JWWで表示されないとき

出力したDXFがJWWで読める形式かどうかを、その場で調べられます。

```bash
python3 tools/check_dxf.py 結果.dxf
```

Windowsでは **`DXF確認.bat` にDXFファイルをドラッグ＆ドロップ**するだけです。
複数まとめて調べられます。

```
OK  バージョン: R12 (AC1009)
    要素: {'LINE': 1025, 'TEXT': 105}
OK  要素の種類はJWWが読めるものだけです。
OK  mmで書かれているとみて問題ない大きさです（実寸 約50m）。
OK  文字コード: Shift-JIS (ANSI_932)

判定: JWWで読めるはずです。
```

`判定: JWWで読めるはずです。` と出るのにJWW側で見えない場合は、まず
**「全体表示」** を試してください。

それでも見えないときは、**どこで落ちているかを切り分けるテストDXF**を作れます。

```bash
python3 tools/make_jww_test_dxf.py
```

単純なものから順に5つできます。番号順にJW-CADで開き、どこから表示され
なくなるかを見ると、原因が1つに絞れます（すべて10m四方の正方形＋対角線）。

| ファイル | 足したもの | 表示されなければ |
|---|---|---|
| `01_線だけ.dxf` | 線4本のみ（レイヤ0） | 読込操作そのものを見直す |
| `02_文字あり.dxf` | 半角と日本語の文字 | 文字が原因 |
| `03_レイヤ4枚.dxf` | 名前付きレイヤ4枚 | レイヤ名が原因 |
| `04_レイヤ19枚.dxf` | レイヤ19枚（本番と同じ数） | JW-CADのレイヤ上限(16枚)が原因 |
| `05_ezdxf版.dxf` | 01と同じ図形をezdxfで出力 | ezdxfが付ける要素（ハンドル等）が原因 |

### 書き出しの実装は2つあります

既定は **`r12`**（`mvce/io/dxf_r12.py`）で、外部ライブラリを使わず、JW-CADが
解釈できる範囲だけを組み立てます。大文字のテーブル名（`CONTINUOUS` /
`STANDARD`）、ハンドルなし、`LTYPE`/`LAYER`/`STYLE` の3表のみという構成です。

**この構成で実機のJW-CADに表示されることを確認済みです（2026-08）。**

もう一方の `ezdxf` は他のCADとの互換性が高いぶん、JW-CADが苦手な要素が
入ります。**JW-CADでは表示されない**ことを実機で確認しているので、他のCADで
開く図面が必要な場合にだけ使ってください。

```yaml
output:
  dxf_backend: ezdxf
```

### 出力先

既定では実行したフォルダに出ます。フルパスで指定もできます。

```yaml
output:
  dxf_path: C:\Users\あなたの名前\Desktop\敷地検討.dxf
```

> **Windowsのパスは `" "` で囲まないでください。** YAMLの二重引用符の中では
> `\U` などがユニコードのエスケープとして解釈され、読み込みに失敗します。
> 囲まずにそのまま書くか、囲むなら `' '`（一重引用符）にしてください。

途中のフォルダが無い場合は自動で作られます。書き出したファイルの場所は
実行後に絶対パスで表示されます。

### 3Dビューア（HTML）

ダブルクリックで開き、マウスで回せます。外部ライブラリもCDNも使わないので
オフラインで動き、そのまま渡せます。最大ボリューム（オレンジ）と斜線制限の
エンベロープ（青の半透明）を重ねて表示します。

## 旧 `jwcad_volume` との関係

`jwcad_volume` はJW-CADの外部変形連携（JWC形式の読み書き、バッチ、exe化）で
実績があるため、そのまま残してあります。計算エンジンとしては MVCE が後継です。
JWW連携をMVCEに載せ替えるのは今後の作業です。
