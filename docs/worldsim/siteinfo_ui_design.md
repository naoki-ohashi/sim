# SiteInfo 入力・確認画面 設計書 v0.2（草案）

> [`siteinfo_field_definitions.md`](siteinfo_field_definitions.md) の項目を、
> [`siteinfo_requirements.md`](siteinfo_requirements.md) の「自動入力は補助、
> 最終確認はユーザー」の原則で入力・確認するための画面設計です。
> API は [`siteinfo_implementation_guide.md`](siteinfo_implementation_guide.md) 3 章。
> 見た目の土台は SiteInfo v0.1（`siteinfo/index.html`）の配色・フォントを引き継ぎます。

## 1. 画面の目的と流れ

SiteInfo の画面がやることは 3 つだけです。

1. 敷地の位置と形を決める。
2. 項目を埋める（自動入力で提案を受け、ユーザーが 1 つずつ確認する）。
3. すべて確認できたら確定し、下流エンジンに渡す。

```
[1 敷地の特定] → [2 項目の入力・確認] → [3 確定・書き出し]
      ▲                    │
      └── 形を直す ─────────┘
```

画面は 1 ページ（SPA）で、左に地図、右に入力パネルを置き、上部のステップ
表示で今どこにいるかを示します。スマートフォンでは縦積み（地図が上、
パネルが下）。

## 2. 画面構成

### 2.1 共通レイアウト

```
┌────────────────────────────────────────────────────────────┐
│ SiteInfo  敷地名 [検証用A敷地]   状態: ● 下書き   版: 3        │
│ ① 敷地の特定  ② 項目の入力・確認 (18/26 確認済)  ③ 確定・書き出し │
├──────────────────────┬─────────────────────────────────────┤
│                      │  パネル（ステップごとに内容が変わる）   │
│   地図               │                                     │
│   (国土地理院タイル)  │                                     │
│   敷地ポリゴン        │                                     │
│   辺番号ラベル        │                                     │
│                      │                                     │
├──────────────────────┴─────────────────────────────────────┤
│ 取得元と免責: 自動入力は補助です。必ず一次資料で確認してください │
└────────────────────────────────────────────────────────────┘
```

- ヘッダの「状態」は `draft`（下書き）／`confirmed`（確定）／`archived`。
- ステップ ② の括弧内は「確認済み必須項目数／必須項目数」。ここが揃わないと
  ③ の確定ボタンは押せない。

### 2.2 ステップ ①: 敷地の特定

| 要素 | 内容 | API |
|---|---|---|
| 住所検索 | 住所・地番を入力 → 候補一覧 → 選ぶと地図が移動 | `POST /geocode`（国土地理院 住所検索） |
| 地図で描く | ポリゴン作図（頂点をクリック、ダブルクリックで閉じる）。頂点のドラッグで修正 | — |
| ファイル取込 | GeoJSON（v0.1／v0.2）、DXF（MVE の `dxf_site` と同じ規約）、座標一覧（CSV: x,y または 経度,緯度） | `POST /sites/import/geojson` |
| 三斜求積 | 三斜の辺長を表で入力 → ポリゴンを生成（形の由来 `survey_triangles`） | クライアント側で生成 |
| 面積表示 | 図形面積（自動）、公簿面積、実測面積を並べ、採用面積をラジオで選ぶ | `PATCH /sites/{id}` |
| 真北 | 図面の上方向と真北の角度。地図上に北矢印を描く | 同上 |
| 平面直角座標系 | 自動判定した系番号を表示。判定できなければ選択させる | `plane.py` |
| 確定ボタン | 「この形で進む」→ `POST /sites` → ステップ ② へ | `POST /sites` |

規則:

- ポリゴンが自己交差していたら赤枠で警告し、進めない。
- 辺には反時計回りに 0, 1, 2… の番号を地図上に描く。ステップ ② の道路・境界の
  入力と対応させる。

### 2.3 ステップ ②: 項目の入力・確認

パネル上部に **「自動入力」ボタン**と取得元の選択（チェックボックス）を置く。
押すと `POST /sites/{id}/autofill` を呼び、結果を項目ごとに反映する。

その下に、項目定義書のグループ（A〜J）をアコーディオンで並べる。各グループの
見出しに「確認済み／必須数」を出す。

#### 項目行の標準形

```
┌─────────────────────────────────────────────────────────────┐
│ 用途地域 ◎必須                                    [確認済み ✓] │
│ ┌─────────────────────┐                                      │
│ │ 商業地域            ▼│  取得元: 不動産情報ライブラリ XKT002   │
│ └─────────────────────┘  取得日時: 2026-09-17 18:20            │
│ 生の値: "商業地域"        [確認する] [自分で入力する] [メモ]     │
└─────────────────────────────────────────────────────────────┘
```

| 要素 | 内容 |
|---|---|
| ラベル | 項目名と必須区分（◎／○／△） |
| 入力欄 | 型に応じた部品（select、数値、テキスト、真偽、JSON は専用フォーム） |
| 出所バッジ | `auto`（青「自動」）／`manual`（灰「手入力」）／`derived`（緑「計算」） |
| 取得元 | 取得元名、データセット、取得日時。クリックで `raw_value` を展開 |
| 確認状態 | 未確認（黄）／確認済み（緑 ✓）／却下して手入力（灰） |
| 差分警告 | 値と `raw_value` が食い違うとき「取得元の値と違います」（橙） |
| 操作 | 「確認する」→ `confirm`。「自分で入力する」→ 入力欄が編集可になり、保存で `reject`。「メモ」→ `note` |

規則:

- 自動入力で値が入っても、**確認ボタンを押すまで確認済みにならない**。
- 手入力で値を変えると、確認状態は未確認に戻る。
- 確認済みの項目は入力欄をロックし、「編集」を押すとロック解除＋未確認に戻る。
- 取得できなかった項目は「取得できませんでした（取得元: …）」と表示し、
  「指定なし」とは表示しない。ユーザーが「指定なし」を選ぶのは手入力。

#### グループごとの特記

| グループ | 画面での扱い |
|---|---|
| A 識別・所在 | 住所は逆ジオコーダの提案を表示。地番は表形式（地番・地目・地積を行追加） |
| B 位置・形状 | ステップ ① の結果を表示。「形を直す」で ① に戻る |
| C 面積 | 4 つの面積を横並びで表示し、採用面積と根拠をラジオで選ぶ |
| D 境界・道路 | 辺ごとの表。地図の辺番号と連動（表の行にマウスを乗せると地図の辺が光る）。種別、道路幅員、道路種別、私道、後退、緩和対象 |
| E 都市計画法 | 用途地域は select。容積率・建蔽率は数値。都市計画道路は「掛かりあり／なし」と名称・幅員。「用途地域が 2 以上にまたがる」を ON にすると 2.3.1 の分割 UI が開く |
| F 形態規制 | 斜線の適用は用途地域から自動導出（`derived`）。ユーザーは確認だけ |
| G 日影規制 | 「規制あり／なし／不明」→ ありなら測定面高さ（1.5 / 4 / 6.5）とプリセット（3h/2h、4h/2.5h、5h/3h、自由入力）。時間は 0.5 刻みの数値。5m 超の時間 ≧ 10m 超の時間でなければ警告 |
| H 法令上の制限 | 法令ごとに 1 行の表。「該当／非該当／不明」の 3 択と内容欄。**不明が残っている数**を見出しに出す。ハザード系は自動入力の提案が入る |
| I 供給施設 | select と備考 |
| J 市場・立地 | 数値。地価は公示地点名と年を併記 |
| K 添付 | ファイル一覧（種別、名称、アップロード日）。ドラッグ＆ドロップ |

#### 2.3.1 用途地域の分割（敷地が 2 以上の用途地域にまたがる場合）

| 要素 | 内容 | API |
|---|---|---|
| 境界のトレース | 地図上で用途地域の境界線を描く（クリックで頂点、ダブルクリックで終了。敷地の外から外へ横切る線）。都市計画 GIS のレイヤを下敷きに表示できる | `POST /sites/{id}/zone-parts/split` |
| 部分の一覧 | 切られた部分ごとに、色分けしたポリゴン、面積（㎡）と割合（%）、用途地域 select、指定容積率、指定建蔽率、出所バッジ | `GET /sites/{id}/zone-parts` |
| 導出値 | 「過半の用途地域」「面積按分した容積率・建蔽率」「覆率」を計算バッジで表示。E グループの `zone_type` / `far_percent` / `bcr_percent` はロックし、ここで確認する | 同上 |
| 保存 | 「分割を保存」→ `PUT`。覆率が 1 ± 0.01 を外れるときは保存できず、どこが欠けているかを地図で赤く示す | `PUT /sites/{id}/zone-parts` |
| 自動入力の提案 | reinfolib の用途地域の交差が 2 件以上のときは、下書きの部分が黄色で入る。ユーザーは境界を直してから保存 | `POST /sites/{id}/autofill` |

規則: 用途は過半の面積の部分の用途地域、容積率・建蔽率は面積の加重平均
（項目定義書 5.1）。画面は導出値を表示するだけで計算はしない。

### 2.4 ステップ ③: 確定・書き出し

| 要素 | 内容 | API |
|---|---|---|
| 確定チェック | `confirm-check` の結果を一覧表示。理由ごとに該当項目へのリンク | `GET /sites/{id}/confirm-check` |
| 確定ボタン | すべて解消したときだけ有効。押すと確認ダイアログ「確定すると版が固定されます」 | `POST /sites/{id}/confirm` |
| 書き出し | GeoJSON（v0.1 互換）、GeoJSON（全項目）、MVE YAML、PDF（項目一覧と取得元・確認者の記録） | `GET /sites/{id}/geojson` ほか |
| 下流へ | 「MVE で最大ボリュームを計算」「HBU-ANALYZER へ」「BVCE へ」のリンク（GeoJSON を渡す） | — |
| 再開 | 確定後に「再開する」→ 理由を入力 → `draft` に戻る | `POST /sites/{id}/reopen` |

未確定のまま書き出すこともできるが、ファイル名に `_draft` を付け、
GeoJSON の `properties.status` を `draft` にする。

## 3. 状態遷移

```
          作成            全必須項目 confirmed
 (なし) ────────► draft ──────────────────────► confirmed
                   ▲                               │
                   │        reopen（理由必須）       │
                   └───────────────────────────────┘
                   │
                   ▼ archive
                archived
```

項目ごと:

```
 (なし) ──自動入力──► unconfirmed ──確認──► confirmed
    │                    │  ▲                  │
    └──手入力────────────┘  └── 編集 ──────────┘
                         │
                         └──自分で入力する──► rejected（手入力値で確定扱い、以後自動入力は触らない）
```

## 4. 表示規則

| 状況 | 表示 |
|---|---|
| 自動入力の値 | 青いバッジ「自動」＋取得元名。確認前は入力欄の背景を薄黄色 |
| 手入力の値 | 灰バッジ「手入力」 |
| 計算値 | 緑バッジ「計算」。編集不可、根拠（元の項目）をツールチップ |
| 確認済み | 緑のチェック、入力欄ロック |
| 取得元と違う | 橙の警告文と「取得元の値を採用」ボタン |
| 取得できず | 灰の「取得できませんでした」。取得元と理由 |
| 必須未入力 | 赤枠。グループ見出しに件数 |

数値の単位は入力欄の右に固定表示（m、㎡、%、時間）。坪は㎡の横に換算表示のみ。

## 5. 技術

- SiteInfo v0.1 と同じく **単一 HTML＋ES modules**（ビルド不要）を第一候補に
  する。地図は Leaflet、3D は CesiumJS（PLATEAU）。フレームワークを入れる場合は
  Preact＋htm 程度に留める。
- API のベース URL は設定で切り替え（ローカルの FastAPI か、将来のサーバ）。
- `field_definition` を `GET /catalog/fields` で読み、**項目行はカタログから
  生成する**。項目の追加でフロントを直さない。
- 変更はすべて API 経由。フロントに業務ルールを置かない（確定条件は
  `confirm-check` の結果を表示するだけ）。
- 免責文は v0.1 の文言を引き継ぐ（「自動取得した行政情報は参考値。正式な確認は
  自治体窓口で」）。

## 6. 受け入れ条件（M6）

- [ ] `sample_site.geojson` を取り込み、ステップ ①→②→③ を経て確定できる
- [ ] 自動入力後、確認ボタンを押さない限り「確認済み」にならない
- [ ] 確認済み項目に対して自動入力を再実行しても値が変わらず、差分警告だけが出る
- [ ] 必須項目が 1 つでも未確認なら確定ボタンが押せず、理由が一覧に出る
- [ ] 法令制限に「不明」が残っていると確定できない
- [ ] 日影規制で「規制あり」を選ぶと測定面高さと 2 つの時間が必須になる
- [ ] 用途地域の分割で、過半の用途地域と面積按分した容積率・建蔽率が表示され、覆率が範囲外なら保存できない
- [ ] 書き出した GeoJSON を HBU-ANALYZER と BVCE が読める（v0.1 キーが揃う）
- [ ] スマートフォン幅で横スクロールが出ない
